# Implementation handoff — session two

Session one is done. **The matcher and `espalier lint` are implemented and the
ten conformance fixtures pass.** This document is the brief for what comes next.

**Read before touching anything**, in this order: `README.MD`,
`docs/MATCHING.MD` (normative — the matcher is a direct transcription of it),
`docs/CONFIG.MD`, `docs/TYPES.MD`, `docs/ERRORS.MD`, `docs/API.MD`,
`docs/cli/lint/README.MD`, `fixtures/README.MD`.

## What exists

`espalier init`, `espalier adopt`, `espalier lint`, `espalier build` and
`espalier explain`.
Node 20+, ESM,
TypeScript, `node:test`, one runtime dependency (`yaml`).

```text
src/pattern.ts      segments, placeholders, shape normalization, overlap
src/compile.ts      the espalier tree → a trie, constraints, ESPALIER.MD docs
src/match.ts        ownership, requiredness, the deepest recognized node
src/repository.ts   config + compile + the visible file set
src/lint.ts         the run, the lint context, issue construction
src/context.ts      emit and its validation, shared by the runner and the API
src/api.ts          check() and runRule(): issues returned rather than printed
src/render.ts       placement, the map, cardinality, every generated byte
src/build.ts        the filesystem half of build: write, delete, --check
src/init.ts         the config, the espalier root, --ignore-all
src/adopt.ts        inference, stub modules, ignore narrowing
src/explain.ts      the prefix form, the file form, ungoverned paths
src/explainText.ts  the human layout for explain
src/output.ts       human and jsonl formatters, --out destinations
src/cli.ts          argument parsing and exit codes
```

`npm test` builds and runs everything: thirty-seven fixtures, nine unit tests for the
sibling-overlap decision procedure — subtle and only partly fixtured — and
thirteen for the programmatic API, which no subprocess fixture can reach. All
green.

`render.ts` reads no files and takes no paths, deliberately: a renderer that
could read a file could produce output depending on something other than the
espalier, and `--check` would stop meaning anything.

## Decisions taken in session one

All of these are now in the documents; the reasoning is there too. They are
listed here only so nobody reopens them by accident.

- **Nothing is deduplicated, and the runner promises no ordering.** Collapsing
  two issues means discarding one of two findings that agreed on the key and
  disagreed on `captures`. Formatters may buffer and reorder; `human` groups by
  path, `jsonl` does not.
- **`--format` and `--out` are independent.** Everything the run says — issues,
  the partial-run warning, an operational failure — goes through the chosen
  format to the chosen destination. Every `jsonl` line carries a `kind`.
- **`emit({path})` accepts any path inside the repository**, governed or not,
  declared or not, existing or not. Only absolute and escaping paths fail.
- **Overlapping dynamic siblings conflict only when they compete for the same
  role** — two leaves, or two directories. A dynamic directory beside a dynamic
  leaf is legal, and the matcher picks by role rather than by first match.
- **Error codes are emergent.** They are chosen at the throw site with no
  central registry, because we do not yet know which failures surface in real
  codebases. Three are load-bearing, pinned by fixtures: `ambiguous_siblings`,
  `inconsistent_capture_names`, `ignored_required_path`.

Taken while writing the `build` fixtures, and now in the documents:

- **`build` reports through the same formatters as `lint`**, with `--format`
  and `--out`, and four kinds: `written`, `deleted`, `drift`, `failure`.
- **A file whose rendered bytes already match is left alone.** A second run
  touches nothing and reports nothing, which is what makes `--check` in CI and
  `build` in a hook liveable.
- **The cardinality paragraph covers the whole subtree the map covers**, not
  just as far as the next placement point. A closed set that stopped early
  would not be closed.
- **The root document is never pruned**, even with nothing placed at it.
- **A dynamic directory's `ESPALIER.MD` body** renders as a section in the
  nearest ancestor placement point's document. It is never a placement point
  itself, so otherwise the prose would be silently discarded.
- **Requiredness reaches any depth.** `[provider]/handlers/webhook.ts` is
  required for every instantiated provider. The `build` doc's worked example
  said otherwise and was wrong; `MATCHING.MD` won.

- **`espalier test` is dropped, and replaced by a library API.** Fixtures,
  assertions, reporting and watch mode already exist in every test framework;
  a command that reimplemented them would be a worse `node:test` with none of
  the tooling around it. The lint context is the only part nobody else can
  supply, so `check()` and `runRule()` supply it and return issues instead of
  printing them. Coverage — which rules no test exercises — falls out of the
  project's existing unused-module tooling, because a rule with no test is a
  module nothing imports. See `docs/API.MD`.

- **Static leaves may be declared optional**, with `export const optional = true`.
  This came out of asking whether catchall nodes were worth keeping at all. They
  are — a catchall is the only way an espalier can reason about a file that does
  not exist yet, which is the whole product — but the partial-overlap case had
  no true statement available to it. Declaring `webhook.ts` under `[client]/`
  says every client has one, and is false. Leaving it undeclared makes the
  client that has one report `unexpected_path`, and is also false. `optional` is
  the third statement, and it is the only correct one.

  It also dissolves a harder problem it was not aimed at. A named sibling of a
  dynamic directory means two irreconcilable things — `stripe/` is a client with
  an extra file, `utils/` is not a client at all — and every precedence rule we
  tried served one and broke the other. With optional leaves nobody needs to
  name a family member, so a named sibling only ever means *replaces the
  catchall*, which is what the matcher already does. No new key, no new
  precedence, no inference of intent.

  Rejected: `webhook?.ts.mjs`. The `?` is reserved on Windows and `package.json`
  declares no OS restriction, so an espalier using it could not be checked out
  there. Optionality is a semantic property like `description` and `rule`, and
  it lives with them. `requiredFiles` already reads the loaded module off the
  trie node, so this costs nothing structurally.

  `adopt` marks the optional line in both formats — `optional: true` on the
  `written` record, `(optional)` after the path in `human`. Without it the
  three `written` lines read identically, which hides the run's least
  confident guess among its most confident ones: `client.ts` was observed in
  every sibling and `webhook.ts` in one. A marker rather than a fifth label,
  because what happened to the file is still that it was written.

- **A `{name}` back-reference matches what a `[name]` earlier in the same path
  captured.** `clients/[provider]/{provider}.ts` requires each provider
  directory to hold a file named after itself. Before this, the espalier could
  only match every filename and leave the naming relationship to a `rule` body
  asking politely and a `lint` function checking afterwards — prose an agent
  may not follow, checked by code someone has to write, for a fact the espalier
  can state. `README.MD` taught that workaround as the answer and no longer
  does.

  One sentence carries it: **a back-reference resolves to exactly one name once
  its capture is bound.** Required per instance like a static leaf, beats a
  dynamic sibling, never ambiguous with a static one. Precedence became three
  tiers — `static > resolved > dynamic` — which is the existing specificity
  rule extended rather than an exception to it, and siblings are now checked
  only against their own tier.

  Braces already meant an extension list, so the rule is positional: braces in
  a constraint leaf are a list, braces anywhere else are a back-reference. The
  two positions are disjoint, so nothing is disambiguated by content. The comma
  survives as a diagnostic for the mistake someone will actually make.

  The trie keys a resolved segment by its authored form rather than its shape.
  Shape-keying is what makes `[provider]` and `[vendor]` one directory under
  two names; two back-references sharing a shape are two different rules, and
  keying them together would have merged them silently.

  Not implemented deliberately: `adopt` does not infer back-references.
  Spotting `stripe/stripe.ts` from one instance is the guess this project
  spent an afternoon removing.

Taken after `explain`:

- **`adopt` declares the intersection of partly-matching siblings**, and reports
  the rest as `uncovered`. The union invents a requirement and then reports it
  unmet; an extra dynamic leaf legalises the future quietly. Both are worse than
  handing the decision back.
- **Two of a thing is a pattern**, for both signals. The threshold is the
  asymmetry, not confidence: a placeholder costs a rename, separate
  declarations forbid the third one.
- **Inside a dynamic directory, the shared filenames are not collapsed by
  extension.** They are the evidence that made it a family, and the fixtures
  `adopt-sibling-directories` and `adopt-repeated-filenames` are a pair —
  reverting either half fails one of them.
- **`adopt` never overwrites a rule module.** A written `rule` body is the whole
  point, and the loss would be silent.

- **`--staged` is gone.** A pre-commit hook already knows its files, and
  `espalier lint $(git diff --name-only --cached)` is one shell substitution.
  Keeping it meant a git-index dependency and a flag nobody could pin without
  making fixtures into git repositories — the same reason the amendment warning
  was dropped.

- **`init` writes no ignore list by default.** Nobody wires an unconfigured
  repository into CI, so the first run's noise is visible only to the person who
  caused it; guessing a source layout before anyone has said what matters would
  also leave `adopt` unpicking a coarse `src/**` on every run. `--ignore-all`
  opts in. `docs/cli/adopt/README.MD` now says its narrowing is conditional.
- **Dotfiles in the espalier are skipped, not rejected.** `init` writes a
  `.gitkeep` so the espalier root survives a commit, and a `.DS_Store` stops
  being able to fail a whole run.

- **`DEFAULT_IGNORE` is settled.** The append-only promise makes an omission a
  one-line fix in any minor and an inclusion stuck until the next major, so the
  bar is "is this file ever a project's own structural decision" rather than "is
  it common". `README.MD`, `CHANGELOG.MD`, `Makefile`, `Dockerfile` and
  `CMakeLists.txt` are absent for that reason, and `default-ignore-list` pins
  their absence as firmly as it pins the list's contents.
- **`WALK_EXCLUSIONS` stays minimal.** Nothing can re-include what it skips, so
  it holds only machinery. Build output directories are absent: `build/` and
  `target/` are real source directories often enough that skipping them would
  silently un-govern a subtree.

- **No git-history integration.** `lint` asks git what the files are and nothing
  more. Anything needing to know what the repository looked like before is out
  of scope, which is what settled the amendment warning below.

Taken while writing the `explain` fixtures:

- **`explain` and `build` share one cardinality function.** The explain doc
  phrased the same fact a second way; two code paths stating one fact is a
  promise to drift, and drift between the direct query and the written
  documentation is the one thing this tool exists to prevent.
- **A path a structural rule owns as a file gets the file answer**, even when a
  dynamic directory also matches it. The double-catch shape makes both true at
  once, and `ownership-dynamic-directory-and-leaf` caught it.
- **The human layout is pinned byte for byte**, by golden files rather than by
  substring. `--format human` is what a person reads; leaving it unfixtured
  meant leaving the read surface unspecified.
- **Ignored is not declared.** An ungoverned path exits `1` like any other
  undeclared path, with `ignoredBy` naming the route.
- **Espaliers partition, they do not compose.** A directory holding a config of
  its own is a child espalier: its subtree leaves the outer one, and every
  command then runs it as a separate run. Discovery and recursion are one
  feature — either alone leaves a subtree ungoverned or gives a path two
  answers. Rules are shared by `import`, never by inheritance, because an
  inherited constraint would make a file's answer depend on which espalier you
  ran. `ignore` demotes a child to plain content, which is what this repository
  needs for `fixtures/`. CONFIG.MD "Nested espaliers"; discovery in
  `src/children.ts`, recursion in `src/nested.ts`, and four `nested-*` fixtures.
- **Every command respects the boundary, not just `lint` and `build`.**
  `explain` and `adopt` both answer from the nearest espalier at or above the
  path, so neither depends on where the command ran. `adopt` also passes over a
  child inside its target, and does not declare it optional — a stub inviting
  the architect to revisit one would be inviting them to break the boundary.
  `init` needed nothing: running it inside a package is how a child is made.
- **A generated document names the children below it.** `## Governed elsewhere`
  exists because the closed-set sentence and an undescribed directory the
  reader can see are a contradiction otherwise. It names them and stops: a
  summary of somebody else's rules is a second source of truth that goes stale
  silently.

## Open questions

- ~~The double-catch shape.~~ **Settled.** Two open sets get two sentences and
  one closing sentence covering both, with no warning and no compiler change.
  See `build-double-catch`.
- ~~Clean fixtures hide matcher bugs.~~ **Closed.** Every fixture that runs
  `lint` now carries an `ownership` map naming the rule that owns each file, and
  it is the one assertion compared exhaustively rather than partially: the
  harness walks the fixture itself, so a file cannot change hands without a
  failure. Six fixtures asserted `exit: 0` and between them pinned four owners;
  eleven fixtures now pin thirty-eight.
- ~~When to harvest the error codes.~~ **Done**, and into `docs/ERRORS.MD`
  rather than `lint`'s page: the set outgrew one command once `build`, `init`
  and `explain` existed. Thirty-five codes, grouped by what went wrong.
  `test/errors.test.ts` scans `src/` for every `fail()` and `failure()` call and
  fails both ways — a code the source throws and the document omits, and a code
  the document lists and nothing throws. Deciding late was fine; letting the
  record drift afterwards would not be.

Open, both raised by dogfooding:

- ~~**`build` deletes provenance-marked files anywhere in the visible set.**~~
  **Closed**, in two halves. `ignore` now confines the sweep, which covers a
  repository storing generated documentation as data — this one's goldens, a
  vendored copy. And a child espalier's subtree leaves the outer run entirely,
  which covers the case the outer run genuinely should not touch. No manifest
  was needed: both answers are about who owns the path, not about what the
  last run wrote. Pinned by `build-ignored-generated` and
  `nested-build-per-child`.
- **Nothing documents how the two forms of `example` are told apart.**
  `TYPES.MD` describes a path form and an inline form and gives each a
  different guarantee, but never says which is which; the code decides on
  "contains a newline" (`src/repository.ts`), so a one-line inline example is
  indistinguishable from a path and fails with `invalid_example`. Two smaller
  gaps follow from the same silence: `cli/explain/README.MD` and
  `cli/lint/README.MD` both show only the path form, and the human lint
  formatter interpolates `example` into a single `Reference implementation:`
  line whatever form it is (`src/output.ts`), so a multi-line one breaks the
  report's indentation. `example-inline` pins the multi-line case, which is the
  only one any document describes.

- ~~`cli/adopt/README.MD` contradicts itself.~~ **Dissolved.** The worked
  example and the Output table disagreed about a `declared` kind, and the
  answer turned out not to be either of them: with optional leaves `adopt` has
  something true to write about a partly-shared file, so `uncovered` has no
  producer left and is gone. The section and the table now describe one run
  that declares every visible file.

## Known gaps

Carrying `TODO`s in the code:

- `src/ignore.ts` evaluates every ancestor level and lets the last match win.
  Git additionally refuses to re-include a path whose parent directory is
  excluded. Ours is more permissive and covers the documented cases.

One thing stands here again: **the specificity tier in `ordered()` is not
observably pinned.** `{` and `[` both sort after every letter, so for any
realistic name the lexicographic tiebreak lands a resolved sibling in the same
place the tier does. Only a static sibling named above `{` would separate them,
and contriving one would pin the contrivance rather than the rule. The tier is
still there, because the map must list siblings in the order ownership
resolves them.

The inline form of `example` was the last of the others,
and `example-inline` now pins both halves of what makes it a second form: it is
exempt from the existence and pattern checks the path form gets, and it renders
as a fenced block rather than a line. The four before it — `addons` setup and
disposal, the compile-time `example` validation from `TYPES.MD`, the generated
description for a constraint module that exports none (`ALIASES` in
`src/render.ts`), and a placement point that exists only because a constraint
was assigned to it — are covered by `addons-shared-resource`,
`addons-disposed-on-failure`, `invalid-example` and `constraint-only-placement`.

`ESPALIER.MD` frontmatter now reaches the renderer through `Espalier.nodes`, a
map beside the trie rather than fields on it. Putting a directory's prose on a
trie node would give a prose-only directory a node, which changes what `lint`
reports as declared at its parent — a build feature would have moved a lint
answer.

**The espalier-amendment warning is not being built.** `README.MD` promised it;
that promise has been replaced with the reasoning for dropping it. The architect
widening a pattern and an agent widening a pattern are the same edit, so a
warning that fired on `espalier/` changing would fire on the intended workflow
and be muted. Telling them apart needs the previous espalier reconstructed from
git and an ownership diff — real, but its only output is a note nobody is
obliged to read, and it would drag git-history integration into a tool that
otherwise only asks git what the files are. Enforcement belongs to whatever can
refuse: the harness, `CODEOWNERS`, a CI path check. The amendment instruction
`build` writes is now imperative, and that is the tool's whole contribution.

## Constraints

- The docs are the specification. If the code and a document disagree, the
  document is right.
- If a document is genuinely ambiguous or contradictory, **stop and report it**
  rather than picking an interpretation.
- Do not change fixtures to make the code pass. A failing fixture is a bug in
  the code until proven otherwise. Session one changed one fixture, deliberately
  and with the architect's agreement, because a design decision invalidated it.
- **A fixture that passes is not the same as a fixture that guards.** Session one
  shipped a case that passed with the fix reverted, because the espalier's
  declaration order let a broken matcher stumble into the right answer. Revert
  your fix and watch the new fixture fail before you believe it.
- Do not add features, flags, or config keys that no document describes.
- Rule modules are user-authored `.mjs` and are ordinary ES modules — no
  sandbox, no bundling.
