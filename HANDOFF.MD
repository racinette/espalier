# Implementation handoff — session two

Session one is done. **The matcher and `espalier lint` are implemented and the
ten conformance fixtures pass.** This document is the brief for what comes next.

**Read before touching anything**, in this order: `README.MD`,
`docs/MATCHING.MD` (normative — the matcher is a direct transcription of it),
`docs/CONFIG.MD`, `docs/TYPES.MD`, `docs/ERRORS.MD`, `docs/API.MD`,

## What exists

`espalier init`, `espalier adopt`, `espalier lint`, `espalier build` and
`espalier explain`.
Node 20+, ESM,
TypeScript, `node:test`, one runtime dependency (`yaml`).

```text
src/pattern.ts      segments, placeholders, shape normalization, overlap
src/compile.ts      the espalier tree → a trie, constraints, ESPALIER.MD docs
src/match.ts        ownership, requiredness, the deepest recognized node
src/repository.ts   config + compile + the visible file set
src/lint.ts         the run, the lint context, issue construction
src/context.ts      emit and its validation, shared by the runner and the API
src/api.ts          check() and runRule(): issues returned rather than printed
src/render.ts       placement, the map, cardinality, every generated byte
src/build.ts        the filesystem half of build: write, delete, --check
src/init.ts         the config, the espalier root, --ignore-all
src/adopt.ts        inference, stub modules, ignore narrowing
src/explain.ts      the prefix form, the file form, ungoverned paths
src/explainText.ts  the human layout for explain
src/output.ts       human and jsonl formatters, --out destinations
src/cli.ts          argument parsing and exit codes
```

`npm test` builds and runs everything: 266 tests, of which 77 are conformance
fixtures and the rest cover what a fixture cannot reach — a repository is not
the right shape for every claim. The programmatic API, config discovery from a
subdirectory, the ignore walk's pruning, the cache, the sibling-overlap decision
procedure, every operational failure code (`test/failures.test.ts`), argument
parsing and output destinations (`test/cli.test.ts`, where "invoked wrongly" has
no tree to describe it), gitignore semantics one pattern at a time
(`test/ignore.test.ts`), and the glob `context.files` matches with
(`test/glob.test.ts`), which is a different language from the one `ignore` uses
and is worth pinning as such. All green. `npm run coverage` adds Node's own
instrumentation, which merges the subprocess runs the fixtures spawn; without
that merge the CLI would read as untested.

Every fixture that compiles is also swept for cross-command disagreement — see
`fixtures/README.MD`, "The agreement sweep". It asserts relationships rather
than answers, so it needs no expectation written for it and runs everywhere. It
roughly doubles the suite's wall time, which is the price of the only assertion
that can see two commands answering differently.

The incremental cache is the only state the tool keeps, and 49 of those tests
are about it — `test/cache.test.ts`. Every clause of cli/lint/README.MD
"Incremental runs" is observed there, and each mechanism has been checked by
removing it and watching the right test fail: the espalier key component by
component, both halves of the read stamp, the glob dependencies, pruning in
both directions, and header validation. A stale pass is silent, survives every
later run, and looks exactly like a clean repository, so a test that passes for
the wrong reason is worth less here than anywhere else.

`test/human.test.ts` exists because every operational failure in this suite was
asserted in `jsonl` — the format an assertion is cheap against — and the
consequence had gone unnoticed: the human formatter's failure path, its
warnings and the block it prints under an unrecognized path were reached by no
test at all. A formatter is the whole of what most people ever see of a tool.

Three things have been measured rather than reasoned about, and none of them
needs revisiting soon. **Scale**: 32,000 files across 8,000 dynamic instances
lints in 0.57s cold, and the curve is linear from 1,000 up — nothing here is
quadratic. **Concurrency**: eight simultaneous runs over one cache leave it
valid, complete and free of temporary files, which is what the per-pid temp plus
atomic rename is for. **Depth**: a 300-level tree neither overflows a stack nor
slows anything down. Encodings were checked too — CRLF in an ignore file, in
`ESPALIER.MD` frontmatter, and a UTF-8 BOM in the config all behave.

A generated document is a pure function of the espalier **and the repository
tree**: `Not described here` lists the excluded paths that are actually present,
so adding an ignored file changes a document and `build --check` says so. That
is the price of a section a reader can check against `ls` rather than against a
glob. `build-not-described` is where the whole of that rendering is pinned.

Both scripts `cd dist/test` and run a bare `node --test` rather than passing a
path glob. Node only expands globs in test paths from v21, the declared floor is
v20, and an unquoted `dist/test/*.test.js` is the shell expanding it — which
makes development POSIX-only for no reason. Discovery from the directory itself
needs neither.

`render.ts` reads no files and takes no paths, deliberately: a renderer that
could read a file could produce output depending on something other than the
espalier, and `--check` would stop meaning anything.

## Decisions taken in session one

All of these are now in the documents; the reasoning is there too. They are
listed here only so nobody reopens them by accident.

- **Nothing is deduplicated, and the runner promises no ordering.** Collapsing
  two issues means discarding one of two findings that agreed on the key and
  disagreed on `captures`. Formatters may buffer and reorder; `human` groups by
  path, `jsonl` does not.
- **`--format` and `--out` are independent.** Everything the run says — issues,
  the partial-run warning, an operational failure — goes through the chosen
  format to the chosen destination. Every `jsonl` line carries a `kind`.
- **`emit({path})` accepts any path inside the repository**, governed or not,
  declared or not, existing or not. Only absolute and escaping paths fail.
- **Overlapping dynamic siblings conflict only when they compete for the same
  role** — two leaves, or two directories. A dynamic directory beside a dynamic
  leaf is legal, and the matcher picks by role rather than by first match.
- **Error codes are emergent.** They are chosen at the throw site with no
  central registry, because we do not yet know which failures surface in real
  codebases. Three are load-bearing, pinned by fixtures: `ambiguous_siblings`,
  `inconsistent_capture_names`, `ignored_required_path`.

Taken while writing the `build` fixtures, and now in the documents:

- **`build` reports through the same formatters as `lint`**, with `--format`
  and `--out`, and four kinds: `written`, `deleted`, `drift`, `failure`.
- **A file whose rendered bytes already match is left alone.** A second run
  touches nothing and reports nothing, which is what makes `--check` in CI and
  `build` in a hook liveable.
- **The cardinality paragraph covers the whole subtree the map covers**, not
  just as far as the next placement point. A closed set that stopped early
  would not be closed.
- **The root document is never pruned**, even with nothing placed at it.
- **A dynamic directory's `ESPALIER.MD` body** renders as a section in the
  nearest ancestor placement point's document. It is never a placement point
  itself, so otherwise the prose would be silently discarded.
- **Requiredness reaches any depth.** `[provider]/handlers/webhook.ts` is
  required for every instantiated provider. The `build` doc's worked example
  said otherwise and was wrong; `MATCHING.MD` won.

- **`espalier test` is dropped, and replaced by a library API.** Fixtures,
  assertions, reporting and watch mode already exist in every test framework;
  a command that reimplemented them would be a worse `node:test` with none of
  the tooling around it. The lint context is the only part nobody else can
  supply, so `check()` and `runRule()` supply it and return issues instead of
  printing them. Coverage — which rules no test exercises — falls out of the
  project's existing unused-module tooling, because a rule with no test is a
  module nothing imports. See `docs/API.MD`.

- **Static leaves may be declared optional**, with `export const optional = true`.
  This came out of asking whether catchall nodes were worth keeping at all. They
  are — a catchall is the only way an espalier can reason about a file that does
  not exist yet, which is the whole product — but the partial-overlap case had
  no true statement available to it. Declaring `webhook.ts` under `[client]/`
  says every client has one, and is false. Leaving it undeclared makes the
  client that has one report `unexpected_path`, and is also false. `optional` is
  the third statement, and it is the only correct one.

  It also dissolves a harder problem it was not aimed at. A named sibling of a
  dynamic directory means two irreconcilable things — `stripe/` is a client with
  an extra file, `utils/` is not a client at all — and every precedence rule we
  tried served one and broke the other. With optional leaves nobody needs to
  name a family member, so a named sibling only ever means *replaces the
  catchall*, which is what the matcher already does. No new key, no new
  precedence, no inference of intent.

  Rejected: `webhook?.ts.mjs`. The `?` is reserved on Windows and `package.json`
  declares no OS restriction, so an espalier using it could not be checked out
  there. Optionality is a semantic property like `description` and `rule`, and
  it lives with them. `requiredFiles` already reads the loaded module off the
  trie node, so this costs nothing structurally.

  `adopt` marks the optional line in both formats — `optional: true` on the
  `written` record, `(optional)` after the path in `human`. Without it the
  three `written` lines read identically, which hides the run's least
  confident guess among its most confident ones: `client.ts` was observed in
  every sibling and `webhook.ts` in one. A marker rather than a fifth label,
  because what happened to the file is still that it was written.

- **A `{name}` back-reference matches what a `[name]` earlier in the same path
  captured.** `clients/[provider]/{provider}.ts` requires each provider
  directory to hold a file named after itself. Before this, the espalier could
  only match every filename and leave the naming relationship to a `rule` body
  asking politely and a `lint` function checking afterwards — prose an agent
  may not follow, checked by code someone has to write, for a fact the espalier
  can state. `README.MD` taught that workaround as the answer and no longer
  does.

  One sentence carries it: **a back-reference resolves to exactly one name once
  its capture is bound.** Required per instance like a static leaf, beats a
  dynamic sibling, never ambiguous with a static one. Precedence became three
  tiers — `static > resolved > dynamic` — which is the existing specificity
  rule extended rather than an exception to it, and siblings are now checked
  only against their own tier.

  Braces already meant an extension list, so the rule is positional: braces in
  a constraint leaf are a list, braces anywhere else are a back-reference. The
  two positions are disjoint, so nothing is disambiguated by content. The comma
  survives as a diagnostic for the mistake someone will actually make.

  The trie keys a resolved segment by its authored form rather than its shape.
  Shape-keying is what makes `[provider]` and `[vendor]` one directory under
  two names; two back-references sharing a shape are two different rules, and
  keying them together would have merged them silently.

  Not implemented deliberately: `adopt` does not infer back-references.
  Spotting `stripe/stripe.ts` from one instance is the guess this project
  spent an afternoon removing.

Taken after `explain`:

- **`adopt` declares the intersection of partly-matching siblings**, and reports
  the rest as `uncovered`. The union invents a requirement and then reports it
  unmet; an extra dynamic leaf legalises the future quietly. Both are worse than
  handing the decision back.
- **Two of a thing is a pattern**, for both signals. The threshold is the
  asymmetry, not confidence: a placeholder costs a rename, separate
  declarations forbid the third one.
- **Inside a dynamic directory, the shared filenames are not collapsed by
  extension.** They are the evidence that made it a family, and the fixtures
  `adopt-sibling-directories` and `adopt-repeated-filenames` are a pair —
  reverting either half fails one of them.
- **`adopt` never overwrites a rule module.** A written `rule` body is the whole
  point, and the loss would be silent.

- **`--staged` is gone.** A pre-commit hook already knows its files, and
  `espalier lint $(git diff --name-only --cached)` is one shell substitution.
  Keeping it meant a git-index dependency and a flag nobody could pin without
  making fixtures into git repositories — the same reason the amendment warning
  was dropped.

- **`init` writes no ignore list by default.** Nobody wires an unconfigured
  repository into CI, so the first run's noise is visible only to the person who
  caused it; guessing a source layout before anyone has said what matters would
  also leave `adopt` unpicking a coarse `src/**` on every run. `--ignore-all`
  opts in. `docs/cli/adopt/README.MD` now says its narrowing is conditional.
- **Dotfiles in the espalier are skipped, not rejected.** `init` writes a
  `.gitkeep` so the espalier root survives a commit, and a `.DS_Store` stops
  being able to fail a whole run.

- **~~`DEFAULT_IGNORE` is settled.~~ Superseded.** The list is no longer applied
  at run time; it ships as data under `ignores/` and `init --lang` copies what
  you ask for into your `ignore`. The bar it was chosen by is unchanged — "is
  this file ever a project's own structural decision" rather than "is it
  common" — and `README.MD`, `CHANGELOG.MD`, `Makefile`, `Dockerfile` and
  `CMakeLists.txt` stay absent for that reason. What went away is the
  append-only promise, which was there to make central correction safe; nothing
  is corrected centrally now, because nothing is read at run time.
- **~~`WALK_EXCLUSIONS` stays minimal.~~ Deleted.** It was the one unappealable
  list in the tool, and it was hardcoded not because those six names are
  universal but because `walk` had no configuration in scope. It has one now.
  Build output directories were absent from it and stay absent from the shipped
  lists: `build/` and `target/` are real source directories often enough that
  skipping them would silently un-govern a subtree.

- **No git-history integration**, and now no git at all. `lint` walks the
  filesystem itself. Anything needing to know what the repository looked like
  before is out of scope, which is what settled the amendment warning below.

Taken while writing the `explain` fixtures:

- **`explain` and `build` share one cardinality function.** The explain doc
  phrased the same fact a second way; two code paths stating one fact is a
  promise to drift, and drift between the direct query and the written
  documentation is the one thing this tool exists to prevent.
- **A path a structural rule owns as a file gets the file answer**, even when a
  dynamic directory also matches it. The double-catch shape makes both true at
  once, and `ownership-dynamic-directory-and-leaf` caught it.
- **The human layout is pinned byte for byte**, by golden files rather than by
  substring. `--format human` is what a person reads; leaving it unfixtured
  meant leaving the read surface unspecified.
- **Ignored is not declared.** An ungoverned path exits `1` like any other
  undeclared path, with `ignoredBy` naming the route.
- **Espaliers partition, they do not compose.** A directory holding a config of
  its own is a child espalier: its subtree leaves the outer one, and every
  command then runs it as a separate run. Discovery and recursion are one
  feature — either alone leaves a subtree ungoverned or gives a path two
  answers. Rules are shared by `import`, never by inheritance, because an
  inherited constraint would make a file's answer depend on which espalier you
  ran. `ignore` demotes a child to plain content, which is what this repository
  needs for `fixtures/`. CONFIG.MD "Nested espaliers"; discovery in
  `src/children.ts`, recursion in `src/nested.ts`, and four `nested-*` fixtures.
- **`build` is all-or-nothing across every espalier, `lint` is not.** The
  difference is what each produces. `lint` writes to a stream: advisory, over
  when the run is, and a sibling's findings are worth having when one package
  is broken. `build` writes files that outlive the run while the exit code does
  not, and a root document sending readers into a directory with nothing in it
  says nothing about why. `--check` is the exception, because it writes
  nothing. Pinned by `nested-build-child-failure`.
- **Every command respects the boundary, not just `lint` and `build`.**
  `explain` and `adopt` both answer from the nearest espalier at or above the
  path, so neither depends on where the command ran. `adopt` also passes over a
  child inside its target, and does not declare it optional — a stub inviting
  the architect to revisit one would be inviting them to break the boundary.
  `init` needed nothing: running it inside a package is how a child is made.
- **A generated document names the children below it.** `## Governed elsewhere`
  exists because the closed-set sentence and an undescribed directory the
  reader can see are a contradiction otherwise. It names them and stops: a
  summary of somebody else's rules is a second source of truth that goes stale
  silently.

   dogfooding passes ran in scratch copies and were discarded, which is why
   nothing was holding the tool to its own claim between sessions.

   The espalier is deliberately thin on style and heavy on the two rules that
   catch drift: a `src/*.ts` header naming a `docs/…MD` that must exist, and a
   `docs/cli/<command>/README.MD` whose command `src/<command>.ts` must
   implement. Both are `read`/`files` rules, so they also keep the dependency
   cache exercised on a real tree. Verified against five deliberate breaks —
   a header pointing at a renamed document, a page for a command nobody wrote,
   a shipped list with no explanation, a test file with no header, and a file
   with nowhere legal to go — each reported and nothing else.

     invalid, producing twelve operational failures. `docs/CONFIG.MD`
     "Suppressing discovery" predicted this exactly; the fix is the `ignore`
     line that document already recommends.

     and `.idea/` were on it; `.claude/`, `.cursor/`, `.windsurf/`, `.continue/`

     `AGENTS.MD` stays off the list — `build` finds its own output by

   - **`src/cli.ts` was the one module of twenty-two without a header
     comment**, hidden behind its shebang. The rule allows a shebang first; the
     file now carries the header the other twenty-one do.
   - **The first root run left a cache inside sixty fixture espaliers**, one of
     them inside a golden tree. Correct behaviour — they were children at the
     time — but `.cache/` is gitignored, so `git status` showed nothing and only
     `init-bare`'s byte-for-byte golden comparison caught it.

14. ~~Two gaps dogfooding found by being asked about.~~ **Done.**

   **`adopt` never wrote a back-reference.** Given `clients/stripe/stripe.ts`,
   `clients/twilio/twilio.ts`, `clients/sendgrid/sendgrid.ts` it produced three
   *optional* leaves, because each name is held by one sibling out of three.
   That espalier is wrong rather than loose: it says a client may hold any of
   those three files, so `mailgun/mailgun.ts` is `unexpected_path` the day it is
   written — the over-specific failure the command exists to avoid, reached
   through the rule that exists to avoid the opposite one. There is now a third
   signal, and `{client}.ts` is what it writes.

   Its threshold is **every instance**, not two, unlike the other two signals.
   Their asymmetry is rename-versus-forbid; this one's is
   `missing_required_file` against a directory that never had the file,
   reported the first time the espalier runs. Two siblings following a
   convention and a third ignoring it is not a convention, and the optional
   leaves are the right answer for it. Pinned by `adopt-named-after-directory`
   and a unit test for the negative.

   **`--no-common-ignore`.** `--lang` was opt-in and the common block was
   unconditional, which is defensible for `.git/` and not for the licence
   group. The flag declines the whole block; there is no config key because
   nothing is applied at run time, so after `init` the way to drop an entry is
   to delete the line. What it costs is stated rather than warned about: no
   `.gitignore` names `.git/`, so a config without either walks the version
   control directory. Loud, immediate, one line to fix. Pinned by
   `init-no-common-ignore`.

## Why the exclusion list is a file

`.espalierignore` rather than an `ignore` key in the config, because entries
need comments and YAML has nowhere natural to put one.

The comments are the point. An exclusion without a reason cannot be reviewed,
and the two kinds are indistinguishable once written: `node_modules/` will never
have a rule, `src/legacy/` does not have one yet. Only the person excluding it
knows which. `espalier build` reads each comment into the documentation for the
directory that entry sits in, so the reason reaches the reader who would
otherwise have to guess — and the tool never supplies one itself, because it has
patterns and not intent.

Two consequences worth knowing. A separate file is easier to let grow than a
block in a config you open for other reasons; the comments are the only thing
holding that in check, which is why an entry without one renders bare. And
`init` no longer escapes anything: `*.swp`, `!foo` and a bare `:` stop being
hazards once they are not YAML.

## Known gaps

Carrying `TODO`s in the code: none. The last one — `src/ignore.ts` being more
permissive than git about re-including under an excluded directory — stopped
being a preference the moment the walk started pruning. `collectCandidates`
never opens an excluded directory, so a negation that appeared to win named a
path no run had looked at, and `explain` answered "not declared" about a file
`lint` could not see. Two commands disagreeing about one path is the failure
this tool exists to prevent. `excludedBy` now stops at the first ancestor that
excludes, which is git's rule and, here, the only self-consistent one.

**Requiredness resolves by specificity, as ownership does.** It did not: a
dynamic directory instantiated for every name at its depth, so
`[area]/[module]/index.ts` beside `clients/[provider]/client.ts` reported every
provider missing an `index.ts` no rule had placed there. Ownership and
requiredness are two questions answered from one tree, and answering them in
different orders is how a repository gets told to create a file nothing
declares. `requiredness-specificity` pins both tiers.

**Everything still uncovered in `src/` is a guard that cannot currently fire**,
and each is annotated where it sits so nobody re-derives it: `readIfPresent` in
`cache.ts` and `readIgnoreFile`'s empty return in `init.ts` (both preceded by
the validation that refuses a named-but-missing ignore file), `version`'s catch
in `cache.ts` (compilation read the same tree first), the trailing `return` in
`match.ts` and `plan`'s fill-in branch in `render.ts` (neither reachable, both
expressing a rule worth keeping), `read` in `build.ts` and `isGenerated` in
`files.ts` (the gap between finding a path and opening it, which only another
process can widen), and `duplicate_structural_rule`. `internal_error` in
`cli.ts` is the last, by design. Coverage is 99.4% of lines; what is left is
that list and nothing else.

`Reporter.object` was the one thing that was simply dead — an interface method
with three implementations and no caller, unused since the commit that
introduced it. Removed.

**`duplicate_structural_rule` cannot currently be reached.** A leaf's trie node
is keyed by its shape and separated by its capture names, and both are derived
from the filename — so two rules landing on one node are two files with one name
in one directory. Every near miss is caught earlier by something else. The guard
stays, because normalization is exactly the kind of thing a later change breaks
quietly, and `test/failures.test.ts` records the reasoning where the next reader
will meet it. Every other documented code except `internal_error` is now
observed firing there.

One thing stands here again: **the specificity tier in `ordered()` is not
observably pinned.** `{` and `[` both sort after every letter, so for any
realistic name the lexicographic tiebreak lands a resolved sibling in the same
place the tier does. Only a static sibling named above `{` would separate them,
and contriving one would pin the contrivance rather than the rule. The tier is
still there, because the map must list siblings in the order ownership
resolves them.

The inline form of `example` was the last of the others,
and `example-inline` now pins both halves of what makes it a second form: it is
exempt from the existence and pattern checks the path form gets, and it renders
as a fenced block rather than a line. The four before it — `addons` setup and
disposal, the compile-time `example` validation from `TYPES.MD`, the generated
description for a constraint module that exports none (`ALIASES` in
`src/render.ts`), and a placement point that exists only because a constraint
was assigned to it — are covered by `addons-shared-resource`,
`addons-disposed-on-failure`, `invalid-example` and `constraint-only-placement`.

`ESPALIER.MD` frontmatter now reaches the renderer through `Espalier.nodes`, a
map beside the trie rather than fields on it. Putting a directory's prose on a
trie node would give a prose-only directory a node, which changes what `lint`
reports as declared at its parent — a build feature would have moved a lint
answer.

**The espalier-amendment warning is not being built.** `README.MD` promised it;
that promise has been replaced with the reasoning for dropping it. The architect
widening a pattern and an agent widening a pattern are the same edit, so a
warning that fired on `espalier/` changing would fire on the intended workflow
and be muted. Telling them apart needs the previous espalier reconstructed from
git and an ownership diff — real, but its only output is a note nobody is
obliged to read, and it would drag git-history integration into a tool that
now does not use git at all. Enforcement belongs to whatever can
refuse: the harness, `CODEOWNERS`, a CI path check. The amendment instruction
`build` writes is now imperative, and that is the tool's whole contribution.

## Candidacy and the ignore lists

What replaced `WALK_EXCLUSIONS` and `DEFAULT_IGNORE`: one walk, one list,
nothing invisible.

`collectCandidates` walks the filesystem and does not descend into a directory
`ignore` matches. `fromGit`, `isGitBacked` and `git_failed` are gone: two
definitions of candidacy that agreed most of the time were a silent-divergence
hazard, and needing another binary installed to know what a file is was a
dependency a CLI tool should not have.

`ignoreFiles` reads the list every repository already keeps. It is read as
`espalier`'s syntax and not as git's — nested files are not read, character
classes and escapes are unsupported — because a second, silently different
gitignore implementation is the thing this was meant to avoid. Patterns land
before `ignore`, so the config wins a disagreement.

**A file it names must exist**, or `ignore_file_missing` stops the run. That is
what decided the default: a key defaulting to `.gitignore` would break every
repository without one, so it is empty, and `init` writes down what it chose.
`init` insists on finding the file before writing anything, and takes
`--ignore-file`/`-i` to name others or `--no-ignore-file` to decline — the two
together are `contradictory_flags` rather than a precedence rule. Tolerating a
missing file was the first design and it was wrong: a typo or a deletion would
leave a repository governing everything and reporting thousands of paths, with
the cause several steps from the symptom.

Files `ignoreFiles` names are invisible unconditionally, like the config
itself: they are configuration the run read. The default name never showed it,
because `_common` covers `.gitignore` anyway.

The three exclusion problems are genuinely different and were repeatedly
conflated while this was being settled. Worth keeping straight:

1. **Traversal.** `.git/`, `node_modules/`, `dist/`. Has an external source of
   truth. Answered by `ignoreFiles`, except for the VCS directory — `.gitignore`
   never lists `.git/`, so it rides in on `ignores/_common.gitignore`, which
   every `init` writes.
2. **Tracked but not architecture.** `package.json`, lockfiles, `tsconfig.json`,
   and also `LICENSE` and `.github/`. Committed on purpose, so no `.gitignore`
   will ever name them. No upstream exists; this is espalier's own opinion,
   shipped as data under `ignores/` and copied into the config — `_common`
   always, a language file per `--lang`.
3. **Undeclarable.** Dot-prefixed paths, which `compile.ts` cannot express and
   `adopt` refuses. Still only ever `ignore`-able. Lifting that restriction is
   open and is not a prerequisite for any of the above.

Fixtures that need an ignore source name it `.gitignore.fixture`, never
`.gitignore`: git honours the real name, so every path such a file excluded
would be a path `git add -A` silently skips and the next clone never receives.
`-i` exists partly so that choice is available.

Pruning had one consequence worth recording: it made a matcher difference into
a correctness bug. See **Known gaps** — the permissive ancestor handling in
`src/ignore.ts` was harmless while candidacy enumerated everything, and wrong
the moment it stopped.

Copied rather than applied is the whole of the change in kind. An upgrade can no
longer alter what a repository governs, and `explain` answers with a line in a
file the user owns instead of the name of a list inside the tool.

## Packaging

Settled while getting the tarball right:

- **MIT**, `LICENSE` written, `Copyright (c) 2026 Andrei Karavatski`. The
  manifest had declared MIT for some time, so the file made true what was
  already claimed rather than choosing anything. Apache-2.0 was the only real
  alternative and was declined: its patent grant is close to theoretical for an
  architecture linter, and the ceremony is not free. `author` is the name
  without an email.
- **`repository`, `homepage`, `bugs`** point at `racinette/espalier`. The first
  is load-bearing: npm resolves relative links in a rendered README against it,
  so without it every `docs/…` link on the package page 404s.
- **`prepublishOnly`** deletes `dist/` and runs the suite. `dist/` is gitignored
  and nothing cleaned it, so `files: ["dist/src", "ignores"]` shipped whatever
  was sitting there — stale JavaScript no test had run against, in a tarball
  that looked normal. Verified both ways: a dry run rebuilds and passes 108
  tests, and a deliberately failing test aborts the publish before a tarball
  exists.
- `ignores/` is in `files`. `LICENSE`, `README.MD` and `package.json` are
  included by npm regardless of that list.

## Constraints

- The docs are the specification. If the code and a document disagree, the
  document is right.
- If a document is genuinely ambiguous or contradictory, **stop and report it**
  rather than picking an interpretation.
- Do not change fixtures to make the code pass. A failing fixture is a bug in
  the code until proven otherwise. Session one changed one fixture, deliberately
  and with the architect's agreement, because a design decision invalidated it.
- **A fixture that passes is not the same as a fixture that guards.** Session one
  shipped a case that passed with the fix reverted, because the espalier's
  declaration order let a broken matcher stumble into the right answer. Revert
  your fix and watch the new fixture fail before you believe it.
- Do not add features, flags, or config keys that no document describes.
- Rule modules are user-authored `.mjs` and are ordinary ES modules — no
  sandbox, no bundling.
